# 關係練習室

給單身與交往中的人的關係課網站。一進來先選版本：

- **課程版**：五堂課的介紹、每一堂的上課內容與互動練習，以及帶領者用的投影片和計時器。
- **劇本殺版**《沒寄出的信》：一場 2.5 小時、6 人（3 男 3 女）的情感推理劇本殺，是五堂課的體驗場。

學員在練習裡填寫的內容只存在自己的瀏覽器（localStorage），不會上傳。

## 本機預覽

```sh
npm install
npm run dev
```

打開終端機顯示的網址（預設 http://localhost:4321/artofdating/）。

## 修改內容

| 想改什麼 | 檔案 |

課程頁是 MDX：一般文字用 Markdown 寫，練習用元件插入，例如：

```mdx
<Exercise title="練習名稱" mode="pair" minutes={10}>
說明文字
<Reflect id="唯一的代號" label="題目" />
</Exercise>
```

- `mode`：`self`（自己）、`pair`（兩人）、`table`（桌組）
- 可用元件：`Reflect`（文字框）、`Spectrum`（光譜滑桿）、`Checklist`（勾選）、`Chips`（標籤多選）、`Lists`（清單）、`Rank`（排序）、`Rewrite`（改寫練習）、`Cards`（抽卡）、`Callout`（提示框）
- 同一頁裡每個 `id` 必須不同，學員的填寫內容是用它來儲存的。改掉 `id` 會讓學員之前填的內容讀不到。

## 帶領者投影片

網址：`/present/`（頁首選單的「帶領者」）。每一堂一份投影片，照上課流程排好：封面、QR code（學員掃描打開這一堂的手機頁面）、今天的流程（每一段幾分鐘）、段落、重點、每個練習的步驟與分鐘數，最後是帶回家的約會實驗。

- **練習倒數**：有 `minutes` 的練習投影片會顯示倒數計時，按 <kbd>T</kbd> 開始／暫停，<kbd>+</kbd> <kbd>−</kbd> 加減一分鐘。時間到會輕響提示。
- **講者畫面**：按 <kbd>S</kbd> 另開一個視窗，看得到講者備註（每張的 `notes`）、下一張、現在時間，以及離下一段預定時間還有幾分鐘。兩個視窗會同步換頁和計時。
- **其他**：<kbd>F</kbd> 全螢幕、<kbd>O</kbd> 總覽、<kbd>B</kbd> 黑畫面、<kbd>D</kbd> 深色／淺色、<kbd>?</kbd> 所有快捷鍵。簡報筆的翻頁鍵可以直接用。列印（⌘/Ctrl + P）會每張一頁，可以另存 PDF 備用。

投影片的文字是另外寫的精簡版，**不會**自動跟著 `src/pages/sessions/*.mdx` 更新。修改課程頁的練習（名稱、步驟、分鐘數）時，記得也改對應的 `src/data/slides/N.js`。上課流程只寫在 `sessions.js` 一個地方，課程頁和投影片都從那裡讀；投影片的段落用**標題**對到流程裡的那一段，改段落名稱時兩邊要一起改（對不到的話，`npm run build` 會印出提醒）。

課程沒有固定星期幾、也不一定每週上，網站的文字都用「上次／下次」而不是「上週／下週」。

課程也不一定在晚上。網站的文字都用「今天／這堂課」而不是「今晚」，時間則全部從 `sessions.js` 的 `schedule` 算出來：

```js
export const schedule = { start: '18:45', meal: '晚餐' }; // 晚上班
export const schedule = { start: '14:00', meal: '下午茶' }; // 週六下午班
export const schedule = { start: '11:30', meal: '午餐' };   // 週日中午班
export const schedule = { start: '14:00', meal: null };     // 不安排用餐（每堂 2 小時）
```

改了之後，首頁的「每次幾點到幾點」、課程頁和投影片上每一段的時間、用餐投影片的「幾點回到座位」都會跟著變。每一堂的流程寫的是每段**幾分鐘**，不是幾點。

`meal` 寫 `null` 就是不安排用餐：五堂的用餐段（30 分鐘）和用餐投影片會自動拿掉，入場破冰後直接進入第一段，每堂變成 2 小時；首頁、網站說明和第 1 堂投影片備註裡「一起吃飯」的說法也會換成不提吃飯的版本。首頁「每一堂的流程」第一段的照片是晚餐桌，不安排用餐時可以考慮換一張。

## 課程介紹頁的設計系統與動態

課程介紹頁（`/course/`）用 [tasteskill](https://github.com/Leonxlnx/taste-skill) 的版型系統，檔案在 `public/assets/`（`system.css`、`motion/`、`layout/`、`moments/` 等）。這些是套件原檔，**不要直接修改**；課程介紹頁自己的樣式寫在 `course/index.astro` 開頭的 `<style>`。

課程介紹頁的動態與特效：

| 位置 | 特效 |
|---|---|
| 英雄區 | 載入時標題、說明和按鈕依序浮現；標題裡的「單身／情侶」輪流替換 |
| 關於愛情的四個擔心 | 數字像里程表一樣滾動；小圖捲到時才畫出來（曲線描繪、點陣逐一亮起、長條伸長） |
| 我們相信的事 | 捲動時一個詞一個詞亮起來 |
| 五堂課 | 標題逐行升起；滑過或點一堂，右邊換成那一堂的照片 |
| 每一堂的流程 | 畫面固定，捲動時三個段落依序展開，右邊照片跟著換 |
| 常見問題 | 照片進入畫面時像相片顯影 |
| 結尾 | 五堂課的關鍵字標籤（滑過會變色） |
| 全站 | 按鈕、連結、卡片的滑鼠與按壓回饋 |

系統設定「減少動態效果」的使用者，會直接看到靜止的完成畫面；沒有 JavaScript 時內容也完整。

注意：tasteskill 的規則建議服務類網站每頁只用一到兩個捲動特效，目前的數量是應需求刻意加多的，所以它的檢查器會列出「特效太多」之類的提醒。

另外，tasteskill 原本讓每個區塊剛好佔一屏或兩屏；在比較矮或比較窄的視窗（例如 1000×650）會出現大片空白或把文字切掉，所以課程介紹頁已改成**區塊高度依內容決定**（`course/index.astro` 樣式最後一段）。英雄區至少一屏，放不下時會自己長高。

### 照片

課程介紹頁的 12 張照片（首頁選版本的兩張也從這裡挑）都是用 AI（Codex 圖像生成）做的示意圖，統一成傍晚燭光、台北窗景的色調，畫面裡不出現人臉。如果改成白天上課，這些照片的氣氛會和實際時段不一樣，可以考慮重新生成白天版本或換成現場照。頁尾有一行「照片皆為 AI 生成的示意圖」。有了課程現場的照片後，可以放進 `public/assets/img/`，再改 `course/index.astro` 裡對應的檔名和 `alt`：

| 位置 | 檔名 |
|---|---|
| 英雄區（滿版） | `ai-hero-*.jpg` |
| 四個擔心 | `ai-worries-*.jpg` |
| 五堂課（每堂一張） | `ai-s1-listen`、`ai-s2-repair`、`ai-s3-choose`、`ai-s4-share`、`ai-s5-journey` |
| 每一堂的流程（三段） | `ai-e1-dinner`、`ai-e2-practice`、`ai-e3-home` |
| 常見問題 | `ai-faq-*.jpg` |

## 劇本殺版《沒寄出的信》

| 網址 | 給誰 | 內容 |
|---|---|---|
| `/mystery/` | 所有人 | 介紹、六個角色、流程、規則（不劇透） |
| `/mystery/play/` | 玩家 | 掃名牌背面的 QR code（或輸入代碼）打開自己的劇本；第二、三幕要等 DM 公布密碼 |
| `/mystery/dm/` | DM | 流程與倒數、梅姐台詞、線索、投票與結局、真相、每個角色的劇本、密碼 |
| `/mystery/print/` | DM | 列印包：角色名牌（含 QR code）、線索卡、七封信、問題卡、觀察表、欣賞卡 |

### 劇本放在哪裡

這個 repo 是公開的，劇本和真相不能直接放進來。所以：

- **原稿**放在 `private/沒寄出的信/`，這個資料夾在 `.gitignore` 裡，**不會進 git**，只存在原作者的電腦上。請另外備份（例如放進私人雲端硬碟）。
  - `roles/<角色>.md`：六個角色的劇本，用 `## 第一幕／## 第二幕／## 第三幕` 分幕。`{{信}}`、`{{選擇}}`、`{{線索:P1}}` 會自動換成對應的內容。
  - `dm.mjs`：梅姐台詞、線索卡、十年前的信、選擇與結局、投票題、真相、出戲流程、問題卡。
  - `passwords.json`：DM 密碼、每個角色的代碼、第二三幕的密碼。
- 改完原稿後執行：

  ```sh
  npm run seal
  ```

  會檢查劇本有沒有缺漏，然後加密成 `src/data/mystery-sealed.json`。**這個加密檔可以公開上傳**，沒有密碼看不到內容。記得把它一起 commit。

### 密碼怎麼用

- **角色代碼**：每個角色一組，印在名牌背面，也做成 QR code。只能打開自己的角色，看不到別人的。
- **第二、三幕密碼**：DM 在流程裡唸出來。要同時有角色代碼和幕密碼，才打開得了那一幕，所以沒辦法偷看下一幕。
- **DM 密碼**：打開 DM 控制台和列印包。

改了角色代碼，就要重新印名牌（QR code 會變）。密碼只存在 `passwords.json` 和 DM 控制台裡，不要寫在公開的地方。

### 當天怎麼帶

1. 事先依報名分好角色，打開列印包印出所有東西，名牌沿中線對折，七封信放進信封。
2. 當天用平板或手機打開 DM 控制台，照「流程」分頁一段一段帶，每段有要做的事、梅姐台詞和倒數。
3. 投票和每個人的選擇記在「投票與結局」分頁，結局會自動照順序組好。
4. 時間從課程的上課時間（`src/data/sessions.js` 的 `schedule.start`）往下算，總長 2.5 小時。

## 部署到 GitHub Pages

1. 在 GitHub 建立 repo（免費帳號需為 **public**），名稱和 `astro.config.mjs` 裡的 `base` 一致（預設 `artofdating`）。
2. 推送到 `main` 分支。
3. 到 repo 的 **Settings → Pages → Build and deployment**，Source 選 **GitHub Actions**。
4. 之後每次推送到 `main`，`.github/workflows/deploy.yml` 會自動建置並發布到
   `https://johnbass.github.io/artofdating/`。

如果帳號或 repo 名稱不同，修改 `astro.config.mjs` 的 `site` 和 `base` 即可。

## 分享給學員

學員多半用手機開啟。LINE 的內建瀏覽器無法下載檔案，關掉後筆記也可能不見，所以在 LINE 群組或 QR code 裡分享連結時，請在網址後面加上 `?openExternalBrowser=1`，LINE 就會改用手機的預設瀏覽器開啟：

```
https://johnbass.github.io/artofdating/?openExternalBrowser=1
```

在 Facebook、Instagram 等 App 裡開啟網站時，頁面上方會提示學員改用瀏覽器開啟。

每一堂頁面底部的「保存我的筆記」會依裝置自動調整：手機顯示「傳給自己保存」（打開系統分享選單），電腦以「下載文字檔」為主，所有裝置都可以「複製全部文字」。
